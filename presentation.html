Technical Decisions

Four Engineering Trade-offs

Decision What I Chose Why Code
Detection Model YOLOv8m over YOLOv8x
~25fps CPU vs ~8fps CPU 		5 cams × 4436 frames = 37 min vs 115 min.
Speed wins when no GPU is available.		 detect.py:81
Event Schema Flat schema — all 12 fields on every event row
Over normalised / event-sourced 		Single-table scan with 4 indexes. No joins for 90% of queries. <2000 events/day makes normalisation waste. emit.py:15
POS Correlation 30-min window instead of 5-min spec
Data-driven override 		Billing clips end at 20:11, nearest POS txn at 20:25. 5-min = zero matches. 30-min reflects real retail browsing lag. metrics.py:53
Storage Engine SQLite over PostgreSQL
Zero-dependency Docker 		docker compose up — no PG service, no healthcheck race, no env vars. All queries <5ms at this scale. database.py:11
Staff Detection — Dual Method
Primary: HSV Uniform Match
Torso region (middle ⅓ of bbox) → HSV mask → >40% pixel ratio = staff. Range: [0,0,0]–[180,255,60]
Secondary: Long Presence Heuristic
Track visible for >8 continuous minutes at 15fps → classified as staff with confidence up to 0.95

Next Steps

What I'd Do With More Time

Four production-grade upgrades that move this from a demo to a multi-store platform.

🖥️ GPU Deployment — YOLOv8x
Switch from YOLOv8m (CPU, ~25fps) to YOLOv8x on CUDA. 3× better mAP for partial-occlusion cases. Enables real-time processing on live RTSP feeds instead of clip-based batch.
detect.py → model = YOLO("yolov8x.pt")
🎨 Per-Store HSV Calibration
Current HSV range [0,0,0]–[180,255,60] over-classifies dark-clothed customers as staff. Auto-calibrate by sampling staff crops from the first 60 seconds of each store's feed.
staff.py → auto_calibrate(cam_01_first_60s)
🐘 PostgreSQL at 40+ Stores
SQLite handles 1 store at <5ms per query. At 40 concurrent stores with write-heavy ingestion, migrate to PostgreSQL with connection pooling and partitioned tables by store_id.
database.py → DATABASE_URL = "postgresql://..."
⚡ Async Streaming Pipeline
Replace batch JSONL replay with WebSocket streaming. Move FastAPI endpoints to async def with asyncpg. Dashboard receives live events — zero polling, sub-second latency.
emit.py → WebSocket + asyncio queue
